## C 部：結構性觀察

1. **權限查詢冇 per-request 快取係根源**：`requirePermission`（2 條查詢）、`hasPermission`（69 處呼叫）、`applyFieldGroupGate`（逐行逐組）各自打 DB。建議喺 `src/lib/rbac/` 加 `loadPermissionSet(session)`（`WeakMap` memo），`requirePermission` 回傳嘅 session 帶住個 set，下游全部讀 set。A-1、A-5、A-12、A-19 一次過解決，預計砍走所有 list API 80–99% 查詢數。
2. **報表 builder 冇記憶化、互相內嵌**：`buildGrossMargin → buildMonthlyClose → buildLongtermSalaryAllocation`，`buildReconciliation` 兩條 rule 各自再叫 `buildMonthlyClose`，`buildShortfall → buildGrossMargin`。建議一個 `src/lib/reports/context.ts`：`withReportContext(fn)` 用 `AsyncLocalStorage` 存 `Map<"close:2026-08", Promise<…>>`，builder 入口查 map。純函數結果唔變，但所有呼叫路徑（route、one-click、AI tools、month-health、postorder-export）一齊受惠。
3. **18 個 page 成頁 `"use client"`**（`guards/import`、`reports/longterm-payroll`、`reports/gross-margin`、`reports/monthly-close`、`reports/ops-digest`、`brokers`、`roster`、`guard-fix`、`quotas`、`roles`、`audit-log`、`triage`、`sites`、`roster-uploads`、`approvals`、`month-close` 等）：初始資料全部靠 client `useEffect` fetch ⇒ 白屏 → loading → 資料（多一個 round trip），而且每頁自己 fetch `/api/sites?take=500`、`/api/brokers?take=500`（同一 lookup 資料喺 9 個 page 重複拉）。建議：page.tsx 做 server component 預取「參考資料」（盤／雞頭／更種，經 `cache()`），互動部分抽 `*Client.tsx`；或者至少加一個共用 `useLookups()` hook＋SWR 式快取。
4. **bytea 欄混喺 metadata 表**：`roster_uploads.file_bytes`、`staff_list_uploads.file_bytes`、`postorder_uploads.*_bytes`。Prisma 預設讀晒所有 scalar（包括 `update()` 回傳值），只要一個地方漏 `select` 就讀幾 MB。建議：(a) 短期全 repo 加 `*_META_SELECT` 常數＋lint 規則（禁止冇 select 嘅 `rosterUpload.find*`）；(b) 長期將 bytes 拆去 `*_files` 子表（1:1），metadata 查詢就天然唔會帶 bytes。
5. **client fetch helper 有兩套**：`src/lib/api-client.ts`（throw 版，`apiGetAll`）同 `src/lib/ui/api-client.ts`（`{ok}` 版）；冇 AbortController、冇去重、冇 stale guard。建議統一一套並內建 abort＋in-flight 去重。
6. **批量寫入 pattern 唔一致**：有啲用 `createMany`（`roster-upload/service.ts:571`），大部分 loop 逐條 create＋逐條 audit；`writeAudit` 冇 `createMany` 版本。建議加 `writeAuditManyTx(tx, inputs[])`。
7. **interactive transaction timeout 冇統一預設**：有 5 s（預設）、8 s、120 s、30 min 幾種。建議 `src/lib/db.ts` 加 `withTx(fn, { kind: "short" | "bulk" })` helper 統一。
8. **index 只喺 schema 宣告，migration 冇 partial index**：熱門 where 欄（`status`、`settlement_broker_id`、`created_at`、`rate_cards` 全部）都冇 index；建議喺 migration 用 raw SQL 加 partial／`CONCURRENTLY` index。
